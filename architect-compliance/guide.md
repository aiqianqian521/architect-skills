# 合规与隐私架构

> ⚠️ **单 atom 调用硬规则（未经 Router 必读）**：交付必须含四件套——**结论 / 证据（行级）/ 风险分级 / 下一步**。风险分级按 `reference/risk-grading-scheme.md` 量化口径（critical/high/medium/low 触发条件+响应时间）判定，骨架参见 [[architect-router]]#原子风险分级与下一步骨架。不得只给结论不分级、不得只分级不给下一步。

## 核心原则

### 1. 数据处理有目的和边界

为每类个人/敏感数据记录目的、合法依据、最小字段、访问角色、处理地点、保留期和删除条件；目的变化必须重新评估。

### 2. 控制项必须映射到证据

每个合规要求都映射到控制、owner、实现位置、测试/审计证据和复审周期。政策文字不能替代运行记录。

### 3. 主体权利可执行

访问、更正、删除、导出和限制处理请求必须有身份校验、范围确认、异步进度、失败重试和完成审计；删除要覆盖缓存、索引、派生数据和备份例外。

### 4. 数据驻留和跨境可见

标记数据位置、跨区复制、第三方处理者、日志和备份位置；未经批准不得把敏感数据发送到未知区域或第三方模型。

## 检查清单

```text
[ ] 是否有数据分类、处理目的、合法依据和 owner？ | 未通过时: 建立《数据清单》表（数据类/目的/合法依据/owner/位置/保留期）逐条补齐；owner 空缺即定为 high 风险。
[ ] 是否有字段级最小化、加密、脱敏和访问审计？ | 未通过时: 对敏感字段逐字段标定最小化/加密/脱敏处置并接访问审计日志；缺审计先接日志再补字段级。
[ ] 是否定义保留/删除/备份例外和可验证证据？ | 未通过时: 写《保留与删除策略》含每类数据保留期+备份例外+可验证证据（日志/审计记录）；无证据即降级为策略、风险标 medium。
[ ] 是否能执行访问、更正、导出、删除和限制处理请求？ | 未通过时: 实现 5 类主体权利端点+身份校验+异步进度+完成审计；用合成主体数据做端到端删除/导出演练。
[ ] 是否记录数据驻留、跨境流动和第三方处理者？ | 未通过时: 在数据清单补位置/跨境复制/第三方处理者列；未批准的跨境或第三方处理立即阻断并登记复审。
[ ] 是否有事件响应、通知、审计保留和复审周期？ | 未通过时: 写《事件响应预案》含通知时限（如 72h）+审计保留期+复审周期（如年度）；无时限即按适用法规补齐时限。
[ ] 是否把合规控制接入测试、CI 或定期审查？ | 未通过时: 把控制项写成可断言的测试/CI 门禁（如"保留期超 30 天的数据不得入库"）；无自动化即先接定期审查排期。
[ ] [策略 vs 机制] 密钥/合规控制/删除是否走 enforceable 机制（env/secrets-manager/gitignore/CI 门禁）而非仅口头规则文档？ | 未通过时: 把每条"规则文字"映射到一个可强制机制；无法机制的标 high 并登记 owner 与人工复核周期。
```

## 常见问题修复指南

### 删除请求只删主表

1. 建立数据 lineage：主表、缓存、搜索索引、事件日志、备份和派生数据。
2. 为每个节点定义删除、匿名化或法定保留例外。
3. 用合成主体数据做端到端删除演练并保留审计证据。
4. 将失败节点纳入告警和人工复核队列。
5. **验证**：用合成主体发起删除请求，断言缓存/索引/派生数据在 SLA 内同步删除；备份例外被审计记录覆盖。

### 合规规则只有文档无机制（策略 vs 机制）

1. 列出所有"政策性规则"（如"不提交真实密钥""保留期 30 天"）。
2. 为每条规则找 enforceable 机制：密钥 → env+gitignore+CI 扫描；保留期 → 入库断言；删除 → 自动化+审计。
3. 无法机制的标 high 并登记 owner 与人工复核周期。
4. **验证**：`git check-ignore -v config.yaml` 命中；CI 密钥扫描对泄漏 fail；无"口头规则无对应机制"残留。
