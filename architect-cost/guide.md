# 成本与供应商架构

> ⚠️ **单 atom 调用硬规则（未经 Router 必读）**：交付必须含四件套——**结论 / 证据（行级）/ 风险分级 / 下一步**。风险分级按 `reference/risk-grading-scheme.md` 量化口径（critical/high/medium/low 触发条件+响应时间）判定，骨架参见 [[architect-router]]#原子风险分级与下一步骨架。不得只给结论不分级、不得只分级不给下一步。

## 核心原则

### 1. 成本模型绑定业务单位

以请求、活跃用户、任务、GB-month、消息或构建次数计算单位成本；不要只报总账单。区分固定成本、变动成本和一次性迁移成本。

### 2. 容量假设显式化

记录流量、峰值、数据增长、保留期、并发、P95/P99、冗余和灾备假设；每个假设写来源、置信度和触发复算条件。

### 3. 先做规模适配，再做优化

单机/SQLite、托管服务、缓存、队列和多区域架构按当前 Tier 选择；未来升级路径必须写清迁移成本，不为未知规模预支复杂度。

### 4. 供应商锁定是架构风险

识别专有 API、数据格式、网络出口、合同和迁移工具；关键数据保留可导出格式，关键能力至少有替代路径或退出成本记录。

### 5. 配额双窗与降级

额度面用**两个嵌套窗口的快照**表达（短窗管突发、长窗管持续，如 5h + 7d），每窗只带 `usedPercent`（夹取 [0,100]）
与 `resetsAt`；百分比缺失/非法时**丢窗**（不是当 0），两窗皆废则整快照为空；抓取失败**降级为 error snapshot**
（含 `updatedAt`）绝不抛进主路径；额度消费必须带**强制幂等键**并在传输回退时复用同一键，调用自带超时。
> cycle-9 A4 真值：lobehub-canary `codexQuota.ts:18-20,115-122,348-374,613-641` → loop `loop-engine/quota_window.py`。

## 检查清单

```text
[ ] 是否有业务单位成本（而非只有月账单）？ | 未通过时: 把总账单拆成每请求/每活跃用户/每任务/GB-month 单位成本；只有总数即补拆分与业务量。
[ ] 流量、存储、峰值和保留期假设是否可追溯？ | 未通过时: 记录每条容量假设的来源/置信度/复算触发条件；无来源即补依据并标置信度。
[ ] 是否区分固定/变动/迁移/灾备成本？ | 未通过时: 分账为固定/变动/迁移/灾备四类并显式标出；混为总账即拆分。
[ ] 是否评估多区域、备份、日志和出口流量的隐藏成本？ | 未通过时: 补多区域跨区费/备份存储费/日志量费/出口流量费估算；未估即标 hidden-cost 风险。
[ ] 是否有预算阈值、owner、告警和超支动作？ | 未通过时: 设预算阈值+owner+超支告警+降级/限流/复审动作；无门禁即接 FinOps 告警。
[ ] 是否记录供应商锁定点、导出能力和替代方案？ | 未通过时: 记专有 API/格式/出口/合同锁定点与导出能力+替代路径+退出成本；无记录即建供应商退出 ADR。
[ ] 复杂架构是否通过规模 Tier 和 YAGNI 论证？ | 未通过时: 按 Tier 论证是否需要此复杂度并写 YAGNI 复算触发条件；过度设计即降级到当前 Tier 方案。
[ ] 额度/配额是否按多窗口快照管理（短窗+长窗），且抓取失败可降级、消费动作幂等？ | 未通过时: 建双窗快照（usedPercent 夹取 [0,100] + resetsAt）；非法百分比丢窗、两窗皆废→None；抓取失败降级为 error snapshot（含 updatedAt）；消费带强制幂等键 + 跨传输复用 + 超时。
```

## 常见问题修复指南

### 估算只有一个总数

1. 把总数拆成请求、存储、计算、网络、日志、备份和人工运维成本。
2. 为每项写低/基准/高三档假设和敏感性排序。
3. 将预算阈值接入告警，定义降级、限流或架构复审动作。
4. 每个重大选型记录退出成本和替代路线 ADR。
5. **验证**：单位成本表可按业务量算出预期账单并与实际账单偏差<10%；超支阈值触发告警有演练证据。

### 供应商锁定未评估

1. 盘点专有 API、专有数据格式、网络出口、合同和迁移工具依赖。
2. 关键数据保留可导出格式(如 Parquet/JSON)；关键能力列出至少一条替代路径。
3. 计算每个关键供应商的退出成本（迁移工时+数据出口费+重写）记录到 ADR。
4. **验证**：每个关键能力有替代路径+退出成本 ADR；关键数据可一键导出标准格式。
