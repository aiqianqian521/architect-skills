# P2.2 Orchestrator run/CLI split -- Effectiveness Check (architect-skills retrospective)

Retrospective verification of `p2.2-orchestrator-run-cli-split-proposal.md` (2026-08-30)
against the executed P2.2 slices E1-E3. Baseline HEAD before P2.2: 29257ae (post-P2.1,
orchestrator.py 1468); final: 18f1038 (orchestrator.py 781).

## 1. Proposal fidelity
- 3 slices, each an independent GREEN commit (E1 388f172, E2 bf1b0f2, E3 8310000) +
  one docs commit (18f1038, ADR-007). No slice reverted; no RED during the split.
- Primary paradigm held: mode 2 (state-machine-step split). The two large run-loop
  methods (run_once single-round OODA 7-step pipeline; run continuous-round controller)
  are independent handlers; orchestrator retains only the composition root + the
  small run-parallel/doctor/status/review/reset block. Mode 1 (responsibility) was
  applied in P2.1 for the helper mixins; P2.2 applied mode 2 to the pipeline body.
- STOP target (orchestrator.py < 800) reached at E3 (781); never exceeded. Final
  Orchestrator class = 555 (< 1500 god-class baseline).

## 2. Folding corrections (swarm rationale) -- all held (extended ADR-007)
1. Gibbs data/contract: the proposal's E1/E2 import lists were INCOMPLETE -- run_once
   additionally uses EVT_ACT_RESULT, build_context_snapshot, date, _STEP_INDEX; run
   uses time, date, check_compatibility, compute_pool_hash, pool_matches, _STEP_INDEX.
   _STEP_INDEX/_STEP_ORDER are module globals ( Cycling back from orchestrator ) -> copied
   verbatim into each mixin (C2 circuit_state precedent) with an equality smoke.
2. Sartre test/red-team F1: two mixins not one -- run calls run_once exactly once
   (one-directional coupling); shared helpers already live in CircuitState/RunState
   (no mixin-to-mixin body dependency). Rejecting the "merge into a ~611-line god-mixin".
3. Sartre F2/F5: build_orchestrator STAYS in orchestrator (Option a) -- it constructs
   Orchestrator at runtime and coheses with orchestrator module-locals (_HERE,
   PROJECT_ROOT, DEFAULT_CONFIG, HAS_YAML, _log); main() already DI-injects it into
   CliRouter. Relocating would create a needless bidirectional cycle and expose >=4
   module-locals. Deleting the dead _legacy_main alone reaches < 800, so
   build_orchestrator and _show_history were NOT moved (not STOP-driving).
4. Sartre F3: the live parser is CliRouter.build_parser (cli_router.py:45 registers
   --min-win-rate); _legacy_main is a 98-line dead duplicate (0 callers). E3 deleted
   it and retargeted test_cli_min_win_rate_flag from a brittle text-scan of
   orchestrator.__file__ to a behavioral assertion on CliRouter.build_parser()._actions
   -- smaller and safer than migrating argparse into main() or a new cli_main.py.
5. Aristotle (read-only): verbatim migration has zero residual risk on closure binding,
   the time singleton, and the adjacent save_checkpoint -> _flush round_start/round_end
   order. F2 deferred test-adds (run() else-branch round_start/round_end recovery; a
   --resume subprocess e2e) recorded as backlog, not blocking. Aristotle's reported
   line numbers drift +5..+11 vs physical -- implementation anchored on AST and
   printed source, never on its line numbers.

## 3. Separation of concerns / coupling
- Final composition: class Orchestrator(ProjectLoader, CircuitState, L2Meta, RunState,
  RunOnceMixin, RunLoopMixin) -- no MRO collision (each mixin owns disjoint method names);
  retention contracts for _run_once_legacy and _safe_run_component (staticmethod) preserved.
- Each new mixin imports only its dependency closure (time, date, logging, EventLog,
  StatusBar, OODASteps, RoundContext, resume_guard, the EVT_* / step_* event builders),
  never orchestrator -> import-cycle-free and unit-importable. _HERE bootstrap +
  _log = getLogger("loop-engine") replicated per the project_loader/circuit_state/
  run_state convention.
- Call-site discipline: the run_once -> run call, the on_transition binding, and the
  save_checkpoint-then-_flush ordering stay wired in Orchestrator mixin composition;
  MRO resolves the moved methods at runtime.

## 4. Risk grading vs outcome
- E1 hit a real defect: ast.get_source_segment strips the leading-line indentation
  (starts at col_offset) -> compile failed "expected indented block". Corrected to
  verbatim extraction via raw lines[lineno-1:end_lineno].join (preserving 4-space
  method indent). This is the surgery invariant the handoff names.
- The false-green trap: run_gate SKIPs ("[gate] SKIP: no ... staged") when nothing is
  staged -> rc 0 but no tests run. E1 tripped this. The corrected per-slice flow is
  write + smoke + git add + commit (-m, argv) -- the pre-commit hook runs the real
  gate -- then verify HEAD advanced (never trust a SKIP rc=0). E2/E3 used it cleanly.
- ConstrainedLanguage hard fact: [System.Text.UTF8Encoding]::new() and .NET type
  creation are blocked ("Cannot create type. Only core types are supported"). File
  writes use cmdlets or Python open(path,'w',encoding='utf-8'); need-UTF-8-without-BOM
  uses Python, not Set-Content. Python source carries no Chinese literals (stdin is
  GBK; Chinese paths ride env vars, Chinese content rides a UTF-8 temp file).
- Cosmetic: the E1 commit subject carries a \ufeff BOM (stdin-pipe artifact); left
  un-remediated (local unpushed branch; rebase risk outweighs cosmetic benefit).
