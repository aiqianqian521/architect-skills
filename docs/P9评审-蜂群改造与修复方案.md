## 三、关键反转：真正的高杠杆项被漏了

### 问题：`type` 枚举过窄造成每次评估的精度损失

`reference/agent-output-schema.json` 和 renderer `VALID_TYPES` 的 12 项枚举，无法表达真实评估中反复出现的高频类型：

| 真实场景出现 | 当前被迫映射 | 损失 |
|-------------|-------------|------|
| `monkey_patch`（运行时替换库函数） | → `design_flaw` | 类型语义丢失，无法按类型聚合统计 |
| `missing_coverage`（无测试覆盖配置） | → `missing_test` | 覆盖类问题被归并错桶 |
| `dup_code`（复制粘贴重复方法） | → `design_flaw` | 失去代码债类型标签 |
| `missing_config` / `hardcoded_config` | → `other` | 高频"配置债"被冲进 other |

**为什么这是根因**：架构评审的价值在执行矫正闭环。当发现类型被拍扁到 `design_flaw/other`，后继的"按类型统计高发维、按类型沉淀基线、金样回归按类型对比"全部失真。这比"15 个 atom 有没有 contract.json"更影响产出质量。

**最优解**：
1. 把 `type` 从**封闭 enum 改为开放字符串 + 推荐值列表**（或扩展枚举到 25-30 项覆盖真实高频：monkey_patch/missing_coverage/dup_code/missing_config/hardcoded_config/config_drift/security_hole/...）。
2. renderer 对未知 type **不再 throw**，而是接受并标 `type_unknown` 归类到待复核（保持宽松、不丢数据）。
3. 同步更新 `reference/agent-output-schema.json` 与 `scripts/render-report.cjs` 的 VALID_TYPES。
4. 在测试方案 T 系列里增加一条"未知 type 不拒收"断言。

## 四、P6 / P2 的最优解（明确回答）

### 关于"P6 涉及的 15 个 atom"
- **不是都要铺开契约**。真实优先级：
  1. **最高**：schema `type` 枚举修复（见第三部分）——影响每一次评估精度。
  2. **次高**：保持 security 试点，作为"契约形态"样板；仅当出现第二个真实蜂群消费维度时，才扩展该维度契约。
  3. **最低（可完全不做）**：为其余 15 个 atom 全量写 contract.json。在没有第二场景验证前做它=投入产出倒挂。
- 正确的做法是把"契约铺开"从"必须完成的修复"降级为"未来的可选建设"，并诚实标注试点状态（`validate-contracts.mjs` 试点模式已经做到这一点）。

### 关于"P2 严格门禁"
- **不开 throw 硬门禁**是正确的最优解。理由：
  - assessment 模式是机器聚合，narrative 常由人填；强制 throw 会让评估无法落档。
  - warning + NARRATIVE_MISSING（当前实现）已让"静默空段"变为"显式提示"，达到目的且不破坏流程。
- 可选：仅在 review 模式（评审改造方案）提供一个 `--strict-narrative` 开关，由调用方决定是否强制。**默认不开。**

## 六、结论

- 方案有没有被 P9 评过？**没有独立评审**；这篇就是评审。
- 最优解不是"把 15 个 atom 契约铺满"，而是**"修根因（schema 枚举）→ 保持克制（契约试点、narrative 用 warning）→ 用 L1 锁定不回归"**。
- 一句话：**门禁语义修对了，契约别铺，把省下的力气拿去修 type 枚举和补 schema 兼容。**

> 📌 P9 复核结论：方案未被独立 P9 评审过，本文即评审——门禁语义修复（P1）正确必要，契约全量铺开（P5）属过早平台化应降级为可选，narrative 保持 warning（P2）优于强制 throw，真正的高杠杆根因是被漏掉的 agent-output-schema `type` 枚举过窄（monkey_patch/missing_coverage 等被迫降级映射致每次评估精度损失），应优先修复并补 L1 断言。

### 7.1 追加证据存档：P0 精度对比报告（2026-09-01）

> 依据 `docs/P0评审精度对比报告.md`，对三个项目用 修复前（render-report.cjs.p9bak，12项封闭 enum）与 修复后（P0，开放字符串 + 26项推荐列表）各跑一次完整评审，量化精度差。
