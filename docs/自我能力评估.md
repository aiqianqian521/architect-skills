## 二、我做不到的部分（需要你的环境配合）

| 改造项 | 为什么做不到 | 需要你提供什么 |
|--------|-------------|--------------|
| **端到端蜂群测试** | 我没有 Bacon/Archimedes/Halley 等 agent 的运行环境，也无法调用 LLM API 发起真实评估 | agent 编排环境（cfuse/cc/codex）+ 项目靶子 |
| **contract.json 实际效果验证** | 写好契约后，需要真实 agent 按契约输出 JSON，才能验证 schema 是否设计合理 | 跑一轮蜂群评估，把 agent 原始输出给我做 post-mortem |
| **冲突检测准确度调优** | architect-arbiter 的关键词匹配规则需要大量真实冲突案例来调优 | 历史上真实发生过的跨维度矛盾案例 |
| **DAG 调度实际运行时验证** | DAG 依赖图设计完后，需要真实并发执行来验证有没有死锁、时序问题 | 多 agent 并行运行的 orchestrator 环境 |
| **健壮性测试（chaos 测试）** | 模拟 agent 超时、输出 malformed JSON、completed:null 等故障场景 | harness 是否支持注入这些故障 |
| **渲染输出与预期对比** | render-report.cjs 升级后的输出格式是否被下游消费方正确解析 | 下游工具（如报告生成器、Obsidian 归档）对输出格式的预期 |

**关键瓶颈**：所有"做不到"的核心原因是——**我没有 agent swarm 的运行时环境**。architect-skills 不是一个纯代码库，它是一个"prompt + 代码 + agent 执行"的混合系统。代码层我可以独立改，但 prompt 层和 agent 行为层需要真实运行来验证。
