# 原子风险分级方案（Risk Grading Scheme）

> 本文件定义 architect-skills 输出风险分级的**量化口径与触发条件**。所有评估输出（单维 atom / 单项目报告 / 横评）的风险分级必须依据本方案，禁止主观判级。
> 设计参考：cspm_agent `cspm_risk_interpretation_scheme.md`（P0-P3 + 评分权重矩阵 + 响应时间）。
> **评分仅用于内部定级，报告不展示具体分数**（防虚假精确）。

## 一、风险等级与触发条件

任一触发条件命中即定该等级（取最高命中等级）。

| 等级 | 触发条件（任一命中） | 响应时间 |
|---|---|---|
| **critical** | ① 明文密钥/凭证入库 ② 可直接利用的漏洞或暴露面 ③ 数据丢失/损坏风险 ④ 变更管控失灵致敏感数据入库（如 `$(...)` 畸形文件名/密钥文件未 gitignore） ⑤ 安全机制整体缺失（无密钥管理设施/无访问控制且涉敏） | 立即 / 24h |
| **high** | ① 单文件 > 800 行 god file ② 配置多源无单一可信源（同一值在代码/compose/env 三处漂移） ③ 边界未收敛致两个 skill 给矛盾结论 ④ 无密钥管理设施（非 critical 时） ⑤ 评而不修：自评 critical 持续 ≥2 轮未清 ⑥ 清单裸问句/修复指南缺验证末步（批量性） | 7d |
| **medium** | ① 单维缺验证末步（非批量） ② 无 healthcheck/resource limit ③ 编码规约缺失（GBK 乱码/无统一 UTF-8） ④ 文档缺关键入口（无 README） ⑤ 无结构化日志/无 metrics ⑥ 测试入口散乱多份 | 30d |
| **low** | ① N/A 维无复检触发条件 ② 文档过载无索引 ③ 命名不规范 ④ 注释/文档质量瑕疵 | 季度 |

## 二、评分权重（内部定级用，不展示）

| 维度 | 权重 | 说明 |
|---|---|---|
| 安全 | 35% | 密钥管理/暴露面/访问控制/变更管控 |
| 可维护性 | 25% | god file/模块边界/配置单一源 |
| 可靠性 | 20% | 超时重试熔断/状态机/幂等/容错 |
| 运维 | 10% | healthcheck/编排/可观测 |
| 文档 | 10% | 入口完整/编码规约/索引 |

> 权重用于在多触发条件同时命中时校准等级（如安全 35% 触发 critical，可维护性 25% 触发 high，取 critical）。报告只写等级 + 触发条件引用，**不写分数**。

## 三、置信度机制（新增 §三，蜂群模式必填）

> 置信度用于标记评估结论的可靠程度，解决 agent 超时、证据不足、无法访问等场景下的"沉默通过"问题。

### 3.1 置信度定义

| 置信度 | 定义 | 判定标准 | 处理方式 |
|--------|------|----------|----------|
| **high** | 高置信度 | 读到直接证据：行级代码/配置文件内容/测试输出可直接复现 | 直接入报告，无需复核 |
| **medium** | 中等置信度 | 基于间接推断：从调用链、依赖关系、设计模式推断，但无直接行级证据 | 入报告，建议第二 agent 复核 |
| **low** | 低置信度 | 仅基于模式匹配或经验规则：如"该模块看起来可能缺乏输入校验" | 入「待复核」章节，必须人工确认 |
| **unknown** | 无法评估 | agent 无法完成评估：超时、completed:null、外部依赖不可访问、所需文件缺失 | **强制显式标记**，不得跳过或默认 low |

### 3.2 置信度使用规则

1. **所有 finding 必须带 confidence 字段**，renderer 发现缺失时自动标记为 `unknown` 并告警。
2. **unknown 不得入正式报告正文**，必须归入「待复核」章节，并说明原因（如"Halley completed:null，设计维度未评估"）。
3. **high 发现被反驳时降级**：若另一 agent 提供反证，该 finding 的 confidence 降为 medium，触发复核。
4. **跨 agent 一致性校验**：同一文件同一行，两个 agent 的 confidence 差异 ≥2 级（如 high vs low）时，renderer 标记为 `CONFLICT_EVIDENCE`。
5. **金样回归时对比置信度**：不仅对比 risk_level，还需对比 confidence。若同条件上次 high 本次 unknown → 触发"评估退化告警"。

### 3.3 与风险等级的关系

- confidence 不影响 risk_level 的判定（风险等级由客观触发条件决定）
- confidence 影响报告的**行动优先级**：两个 medium risk 的 finding，high confidence 的先修，unknown 的后修或人工确认
- 整维全部为 unknown 时，该维状态标为 `missing` 而非 `covered` 或 `partial`

## 四、使用规则

1. **每个 covered/missing 维必须标风险等级**（critical/high/medium/low）；partial 标其最高缺口等级；N/A 标 low（缺复检时）或不标（带复检时）。
2. **定级必须引用触发条件编号**：如 `critical（C1，触发①：明文密钥入库）`，禁止只写 `critical` 不给依据。
3. **禁止主观词**："严重""比较重要""可能有问题"不可作为定级依据，必须落到§一触发条件。
4. **取最高命中**：一处命中 critical，整维即 critical，不因其他项 low 而降级。
5. **响应时间**写入"下一步"字段（如 `下一步：24h 内轮换密钥并移 config.yaml 入 .gitignore`）。
6. **置信度必填**：每个 finding 的输出必须包含 confidence 字段，renderer 会校验。

## 五、与 Router 输出协议的关系

Router「### 原子风险分级与下一步骨架」要求每次输出含 `结论 / 证据 / 风险分级 / 下一步`。本方案定义**风险分级**的量化口径，补足 U4 的"靠主模型自觉"缺口（反评 S1）。

Router「输出模板硬性清单（强制）」section 要求本方案被引用——定级时必须 `依据 reference/risk-grading-scheme.md §一①`。

蜂群模式下，agent 输出必须同时满足：
- risk_level：依据 §一触发条件
- confidence：依据 §三置信度定义
- risk_scheme_ref：引用具体触发条件编号

## 六、金样对照

`output/golden/` 下三项目 v2 报告为本方案的金样实例：
- 等级定级均带触发条件编号（如 C security `critical①`、A `critical④`、B `critical①god file>800行`）
- 新增评估可对照金样回归，确认定级口径一致

## 七、安全约束（借鉴 cspm）

1. 评估为只读分析，不修改被评项目配置
2. 输出严禁包含被评项目的 AK/SK/STS/TOKEN/SECRET 明文（密钥证据须脱敏）
3. 明文密钥发现即 critical，不因"个人项目"豁免
