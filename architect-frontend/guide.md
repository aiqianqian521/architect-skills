> ⚠️ **单 atom 调用硬规则（未经 Router 必读）**：交付必须含四件套——**结论 / 证据（行级）/ 风险分级 / 下一步**。风险分级按 `reference/risk-grading-scheme.md` 量化口径（critical/high/medium/low 触发条件+响应时间）判定，骨架参见 [[architect-router]]#原子风险分级与下一步骨架。不得只给结论不分级、不得只分级不给下一步。

## 核心原则

### 1. 用户流程先于组件堆叠

先定义关键用户旅程、加载/空/错误/权限状态和成功指标，再划分页面、feature 和共享组件。

### 2. 状态按生命周期归属

服务器状态、URL 状态、表单状态、临时 UI 状态和跨页面客户端状态分开管理；避免把所有状态塞进一个全局 store。

### 3. 组件边界可替换

组件通过明确 props/events 或协议协作；业务规则不泄漏到纯展示组件，数据获取、缓存和副作用位于可测试边界。

### 4. 可访问性和性能是验收条件

键盘操作、语义结构、焦点、对比度、屏幕阅读器和 reduced motion 进入验收；同时跟踪 LCP、INP、CLS、bundle size 和错误率。

## 检查清单

```text
[ ] 是否有关键用户旅程和所有加载/空/错误/权限状态？ | 未通过时: 画关键用户旅程图并列出加载/空/错误/权限四态；缺态即补到设计稿与测试用例，旅程序列缺失标 medium。
[ ] 状态是否按服务器/URL/表单/UI 生命周期分层？ | 未通过时: 按服务器(URL cache)/URL/表单/临时 UI/跨页客户端五类拆分全局 store；混存的改为按生命周期归属。
[ ] 组件边界是否避免跨 feature 隐式依赖？ | 未通过时: 用 props/events/协议显式声明边界；业务规则从纯展示组件剥离到可测试边界；隐式依赖标 high。
[ ] 是否有键盘、焦点、语义 HTML、对比度和屏幕阅读器验证？ | 未通过时: 接 a11y 自动化(axe-core)+键盘手动回归+对比度≥4.5:1；缺项补到验收门禁。
[ ] 是否测量 LCP/INP/CLS、bundle size 和运行时错误？ | 未通过时: 接 Web Vitals 上报+bundle 分析(size-limit)+前端错误监控(Sentry 类)；无基线即先打基线再设阈值。
[ ] 是否有组件契约测试和关键旅程 E2E？ | 未通过时: 为共享组件加契约测试(Storybook/props 断言)+关键旅程 E2E；纯手测改为自动化并入 CI。
[ ] 设计 token、主题和版本是否有单一真相源？ | 未通过时: 把 token 收口到单一变量文件(theme.tokens)+版本化；散落硬编码改为引用 token。
```

## 常见问题修复指南

### 页面能显示但关键旅程不稳定

1. 用用户旅程列出所有状态和失败路径。
2. 将数据获取、状态转换和展示拆成可测试边界。
3. 为键盘/屏幕阅读器和网络慢速场景增加回归用例。
4. 用真实构建产物测量性能，不用开发环境主观判断。
5. **验证**：用真实构建产物跑 Lighthouse/a11y 自动化，关键旅程 E2E 绿；Web Vitals 达 LCP<2.5s/CLS<0.1 基线。

### 全局 store 塞满所有状态

1. 列出当前全局 store 的字段并按服务器/URL/表单/临时 UI/跨页客户端分类。
2. 服务器状态移到数据层（TanStack Query/SWR 类），URL 状态归 URL，表单状态归表单库。
3. 仅真正的跨页客户端状态留全局 store。
4. **验证**：每类状态有独立管理边界；DevTools 中全局 store 字段数显著下降；组件单测不依赖全局 store。

## 展示系统架构（Dashboard / Display System）专项

> 新增能力：2026-10-01 · 面向"多币种×多指标×多止盈方案"的实时展示系统结构评估。
> 来源蒸馏：other_project/NextChat（Next.js+React+react-router+zustand+clsx，前后端分离 + export 静态产物）与 webui_skill 选型库（recharts/liveline、Virtuoso、motion 等）。

### 核验清单（展示系统专项，在 FRO-01~07 基础上补充）

```
[ ] 数据是否分层（总览摘要 / 币种 / 引擎 / 方案明细 / 回测 / 账户资金）？| 未通过→ 一页塞全部 = 数据爆炸，改 6 层嵌套路由。
[ ] 路由是否支持深链接直达（hash 路由 #/coin/ETH/engine/chanlun/scheme/t1t2r288）？| 否→ 用 hash 路由，刷新/分享可还原视图。
[ ] 前端是否前后端分离（只消费 REST API + token 鉴权，不旁路数据库/文件）？| 否→ 一律走后端接口，避免逻辑二处维护。
[ ] 大表/历史数据是否做虚拟滚动？| 否→ 大表不虚拟滚动 = 首帧卡死，用 Virtuoso 类组件。
[ ] 图表是否做"图表池按需实例化 + 节流刷新"？| 否→ 全部图表同时渲染 = 卡顿，改为懒加载 + 30s 默认刷新。
[ ] 空/加载/错误三态是否齐全？| 否→ 缺三态 = 接口抖动时白屏/误导，补 skeleton/empty/error 兜底。
[ ] 展示层是否引入未来数据逻辑？| 命中→ 红线违规，任何展示层只读已收盘 bar，不得含预测。
[ ] 是否有设计 token/主题单源？| 否→ 收敛 token 到单变量文件，组件引用而非散落硬编码。
```

### 常见问题修复指引（展示系统）

1. **页面卡顿**：不是加缓存，而是改架构——图表池懒实例化、大表虚拟滚动、节流刷新、合并接口返回摘要再按需取明细。
2. **数据对应不上**：核对 /api/dashboard 顶层契约字段（kline/account/events/signals/funds/trades），前端用同一 schema，双端校验。
3. **表单/状态混乱**：按生命周期归类状态（服务端/REST URL/表单/临时 UI/跨页），别全塞全局 store。

### 交付必须

- 六层页面（总览→币种→引擎→方案→回测→账户）可路由直达；
- 图表池 + 虚拟滚动 + 三态兜底，默认节流刷新；
- 全接口走后端令牌鉴权 REST；
- 破框审计：展示层零未来数据。
